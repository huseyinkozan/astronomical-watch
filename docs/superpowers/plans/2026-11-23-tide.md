# Tide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show an approximate tide from the Moon and the place's lunitidal interval: a corner gauge, a wave corner icon, an Info part after the Moon, and the portal's setting.

**Architecture:** A host-tested model (`main/Tide.*`) turns the Moon's upper transits (computed once a day into `Sky::Day`, copied into `FaceTable` for the always-on face) and the interval setting into a `Tide::State`; main.cpp and AlwaysOn compute that state and pass it to the gauges (`Corners::Context`) and the icon (`FaceText::Inputs`); `SkyPages` draws the Info part. The Info page gives its battery and about parts to the settings page to make room (each page holds at most eight parts: `PartOrder`'s 3-bit fields).

**Tech Stack:** ESP-IDF 6.1, C++17, LVGL 9; host tests with g++ (`sh tests/run_host_tests.sh`).

**Spec:** `docs/superpowers/specs/2026-11-23-tide-design.md` (mock-ups `2026-11-23-tide/mock.png`, `mock2.png`).

## Global Constraints

- Code style of CLAUDE.md: `m_`/`s_` prefixes, braces, spaces inside parentheses, index `for` loops, no exceptions or templates, English everywhere; every visible text from `main/Language.*` in English and Turkish.
- Enums saved in NVS are appended, never renumbered: `FaceConfig::GaugeItem` (TideGauge = 21), `FaceConfig::CornerItem` (TideIcon = 19), `Corners::Kind`, `FaceTap::Target`, settings items, the settings page's parts.
- The Info page's parts are renumbered (Battery and About leave it): its saved order and hidden mask fall back to the defaults once; accepted by the owner.
- Without the interval setting (`-1`, the default) nothing shows the tide: the gauge is empty, the icon draws nothing, the part asks for the setting.
- Colours: rising cyan `0x40D0E0`, falling blue `0x4080E0`; the icon's water `0x4080E0` and its surface line `0x96C8FF` whatever the direction.
- The icon (B3, `mock2.py` shape 2): a 44 px box; calm line at 20 % of its height; the crest at `0.2 + 0.8 * level` of the height; the surface `(x / 0.68)^2` up to 68 % of the width, then `1 - ((x - 0.68) / 0.32)^0.6`.
- Board work waits for the owner (Task 7); every earlier task ends with host tests and both builds (development and `build-release`).

## Review Focus

1. A day without the Moon's upper transit (about one a month): the model must bridge the gap from the neighbouring transits, not drop to "unknown" — Task 1's `noTransitDay` test.
2. The interval near its maximum (745 min) early in the day: high water from yesterday's transit — Task 1's `longIntervalEarly` test, and four transits in `Sky::Day` (yesterday to the day after tomorrow).
3. The setting off: no gauge fill, no icon, the part's message — Task 1's `off` test and Task 3's `tideOff` gauge test.
4. A watch with a saved Info order or hidden mask of the old eight parts: no crash, the defaults — Task 2's `oldInfoOrder` test.
5. The tap on the gauge or the icon with the Info part hidden: opens the page's first part as for any hidden part (existing FaceTap rule) — Task 3's FaceTap test.

### Task 1: The tide model

**Files:**
- Create: `main/Tide.h`, `main/Tide.cpp`
- Test: `tests/TideTest.cpp`; Modify: `tests/run_host_tests.sh`, `main/CMakeLists.txt` (source list)

**Interfaces:**
- Produces:
  ```cpp
  class Tide {
  public:
      static const int TransitCount = 4;   // yesterday, today, tomorrow, the day after (0: none that day)
      static const int Off = -1;           // the setting's "no interval"
      struct State {
          bool valid;          // an interval set and two transits around the moment
          int level;           // thousandths, 0 low water, 1000 high water
          bool rising;
          int64_t nextHigh;    // Unix seconds, 0 when unknown
          int64_t nextLow;
          int spring;          // thousandths: 1000 at new and full Moon, 0 at the quarters
      };
      // moonAge in days (Astronomy's phase age).
      static State at( const int64_t transits[TransitCount], int intervalMinutes, double moonAge, int64_t now );
      // The high (true) and low waters in [from, to), in time order; returns how many (at most `max`).
      struct Water { int64_t time; bool high; };
      static int waters( const int64_t transits[TransitCount], int intervalMinutes, int64_t from, int64_t to,
                         Water out[], int max );
  };
  ```

- [ ] **Step 1: Write the failing tests** in `tests/TideTest.cpp` (the style of `tests/CycleTest.cpp`: `check( name, value, expected )`, a count of failures, "Tide: N checks, M failures"). With transits 24 h 50 min apart (`T0 = 1782000000`, `T1 = T0 + 89400`, …, `T2`, `T3`) and the interval 320 min:
  - `atHighWater`: `at( t, 320, 7.4, T1 + 320*60 ).level == 1000`, `.valid`.
  - `atLowWater`: half the period later (`T1 + 320*60 + 44700/2`) the level is 0 (±2).
  - `risingBeforeHigh`: one hour before high water `.rising == true`; one hour after `.rising == false`.
  - `nextTimes`: at `T1`, `nextHigh == T1 + 19200` and `nextLow == T1 + 19200 + 22350` (the low before that high, at `T1 - 3150`, has passed).
  - `off`: `at( t, Tide::Off, … ).valid == false`.
  - `noTransitDay`: transits `{ T0, 0, T2', T3 }` (today without one; `T2' = T0 + 2*89400`) still gives `.valid` and the level at `T0 + 320*60 + 89400` (the bridged transit) is 1000 (±5).
  - `longIntervalEarly`: interval 745 at `T1 + 60` (just after today's transit): valid, high water from `T0`'s second half period.
  - `spring`: age 0 gives `spring` 1000, age 7.38 gives under 50, age 14.77 over 950.
  - `waters`: over one day from `T1` there are four, alternating, the first the high at `T1 + 19200`.
- [ ] **Step 2:** Run `sh tests/run_host_tests.sh` — Expected: TideTest does not compile (Tide.h missing).
- [ ] **Step 3: Implement `Tide::at` and `Tide::waters`.** Each pair of neighbouring non-zero transits `Ta < Tb` spans two high waters at `Ta + I` and `Ta + I + (Tb - Ta) / 2`; a zero entry is bridged by the next non-zero one (that pair spans four half periods). For the moment `t`, find the pair with `Ta + I <= t < Tb + I`, the half period `P = (Tb - Ta) / k` (k = 2, or 4 across a bridged day), the phase `f = (t - Ta - I) / P` modulo 1; `level = round( 500 * ( 1 + cos( 2π f ) ) )`, `rising = f >= 0.5`; next high and low from the phase. `spring = round( 1000 * |cos( 2π · 2 · age / 29.530589 )| )`.
- [ ] **Step 4:** Run `sh tests/run_host_tests.sh` — Expected: "Tide: … 0 failures", all other suites unchanged.
- [ ] **Step 5: Commit** "Add the tide model: the Moon's transits plus the place's interval".
