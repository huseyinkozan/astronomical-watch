# Memory (Table Template, Shared Styles, Freeing Far Pages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the internal heap free: the information page's tables drawn by one object per
part, shared styles for the remaining objects, far pages freed, without any visible change.

**Architecture:** A new `TablePart` (LVGL object + our own text array, drawn on
`LV_EVENT_DRAW_MAIN`) replaces the label rows of `SkyPages` and the setup-info part. A few static
`lv_style_t` replace per-object style calls. `Display` frees the information and settings pages
when neither they nor a neighbour is shown (and the information page while the portal runs
unless shown), rebuilding through today's `ensureBuilt`.

**Tech Stack:** ESP-IDF v6.1, LVGL 9, C++17; host tests with g++.

**Spec:** `docs/superpowers/specs/2026-11-19-memory-design.md`

## Global Constraints

- Nothing changes on the screen: every page's screenshot (fixed scene) equals the reference
  pixel for pixel, apart from values that follow the clock (the time part's seconds).
- Each step is measured on the board: internal heap free and largest block at active start, after
  the information page, after the settings page, with the portal on; the LVGL and main stack
  margins from the event log.
- Portal on and idle: at least about 90 KB of internal heap free after step 3.
- No longer minute wakes; no slower swipes beyond today's on-demand build.
- CLAUDE.md style; no abort on an allocation failure; LVGL only in its task with the display lock.

## Review Focus

1. The prayer row that is next (amber name and value) moves at each prayer and at midnight: the
   table redraws with the new colours.
2. Turkish and English names longer than their column are cut (clipped) as today, not wrapped.
3. `SkyPages::show` / `Display::showSetupInfo` / `showSetup` called while their page is freed:
   no access to freed objects, and the next build shows the current values.
4. The portal's countdown and on/off state on the settings page after the page was freed and
   built again.
5. The development screenshot of a part on a freed page (`S <page>`) builds it first.

### Task 1: Table template

**Files:**
- Create: `main/TablePart.h`, `main/TablePart.cpp`, `tests/TableTextTest.cpp`
- Modify: `main/SkyPages.h/.cpp`, `main/Display.h/.cpp` (setup-info part), `main/CMakeLists.txt`,
  `tests/run_host_tests.sh`

**Interfaces:**
- Produces: `class TableText` (host-testable, no LVGL) in `TablePart.h`:
  `bool set( int row, int cell, const char *text )` (true when the text changed; cut to the
  cell's buffer), `bool setColour( int row, uint32_t rgb )`, `const char *text( int row, int cell ) const`;
  `class TablePart` with `void build( lv_obj_t *parent, const Layout &layout )`,
  `TableText &text()`, `void refresh()` (invalidates only when something changed since the last
  refresh). `Layout`: title, row count, per row one or two values or a full line, the columns
  (name x/width, value widths), the first row's y and the row pitch.

- [ ] **Step 1:** Reference screenshots of every page with the current build
  (`python tools/screenshot.py --out <scratch>/ref`, development build); note the row pitch and
  the columns of each table part from them.
- [ ] **Step 2: Failing host test `tests/TableTextTest.cpp`:** `set` returns true the first time
  and false for the same text; a text longer than the cell is cut and still NUL-terminated; a row
  or cell out of range returns false and writes nothing; `setColour` returns true only on change.
  Add it to `tests/run_host_tests.sh`. Run: `sh tests/run_host_tests.sh` → Expected: the build
  fails (no TablePart.h).
- [ ] **Step 3:** Implement `TableText`; run the host tests → Expected: "Table text: N checks, 0 failures".
- [ ] **Step 4:** Implement `TablePart` (draw: title grey, names grey, values white unless a row
  colour; full lines centred; clipped to their column) and convert Sun, Twilight, Prayer, Moon and
  Time in `SkyPages`, then the setup-info part in `Display` (its own geometry: names at x 30,
  values 220 px, 36 px pitch).
- [ ] **Step 5:** Development build; screenshots of every page compared with the reference
  (pixel diff; only clock-following values may differ). Heap at each state (temporary log, removed
  before the commit) and the event log's stack margins.
- [ ] **Step 6:** Commit with the measured numbers.
