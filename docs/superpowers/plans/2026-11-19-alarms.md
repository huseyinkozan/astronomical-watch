# Alarms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The countdown's end, sky-event alarms and clock-time alarms ring through the speaker;
alarms are defined in the portal, switched on the watch, shown by three corner icons, and keep the
watch asleep (never off) while pending.

**Architecture:** A host-tested `Alarms` module turns definitions into due times; `main.cpp`
caches them in RTC memory, chooses the sleep (minute, alarm, hourly battery check) and rings
through a `Ringer` (a sound task over `Sound`) with an overlay drawn by `Display`. Storage,
portal, clock page part and corner icons follow the existing FaceStore / WorldClock /
ClockPages / FaceConfig patterns.

**Tech Stack:** ESP-IDF 6.1, C++17, LVGL 9, esp_codec_dev (ES8311), host tests with g++.

**Spec:** docs/superpowers/specs/2026-11-19-alarms-design.md

## Global Constraints

- CLAUDE.md style: PascalCase classes and files, camelCase, `m_`/`s_` prefixes, a function's `{`
  on a new line, spaces inside parentheses, index `for` loops, no exceptions/RTTI/templates.
- Every user-visible text in `main/Language.*` in English and Turkish; the portal's Turkish in
  `data-tr`; `lv_label_set_text_fmt` never with `%f`.
- Sound: 1000/1500 Hz alternating beeps, 100 ms tone + 150 ms silence, 5 ms ramps, level −18 dB
  rising 3 dB every 2 s to −6 dB (register 0x32: 0x9B → 0xB3), never above −6 dB; the codec's ADC
  side off while ringing; ringing stops on a tap, a PWR press or after 60 s.
- At most 4 alarms; offset −120 … +120 min; weekday bits Monday first, none = once.
- A due time at most 10 min late rings, later is skipped (logged); a "once" alarm switches off
  after it rang or was skipped.
- Weekdays select the day on which the alarm rings.
- Alarm pending (an alarm on or the countdown running): never power off; deep sleep with a timer;
  an hourly battery-check wake while the always-on face is off; below 10 % the face is off and the
  watch powers off at ≤ 2 % with VBAT ≤ 3.50 V, or VBAT ≤ 3.40 V.
- Nothing extra (no wake, no computation beyond a flag check) while no alarm is pending.
- `sh tests/run_host_tests.sh` green after every task; build with `idf.py build` clean.

## Review Focus

1. A reset, crash or new image in the alarm minute: the alarm rings once, within 10 min, never
   twice (a "last rung" record in RTC memory). Test: Task 1 `lateAndRepeat` cases.
2. A portal save that moves the clock, the location, the offset or the zone: no due time from the
   old inputs is used. Test: Task 1 `inputsChanged` (the cache key) and Task 4 board check.
3. A DST change night with a 03:00 alarm: it rings once at 03:00 of the new offset. Test: Task 1
   `dstChange`.
4. An alarm while the portal's Wi-Fi runs (heap: Wi-Fi + I2S + sound task): no crash; heap and
   stacks logged. Test: Task 3 board check with the portal on.
5. PWR during ringing stops the sound and does not end active mode; after ringing the watch
   still sleeps and wakes for the next alarm. Test: Task 4 guided test `alarm`.

### Task 1: The Alarms module (host-tested)

**Files:**
- Create: `main/Alarms.h`, `main/Alarms.cpp`, `tests/AlarmsTest.cpp`
- Modify: `tests/run_host_tests.sh` (build and run `alarms_test`), `main/CMakeLists.txt` (source)

**Interfaces:**
- Produces:
  - `enum Alarms::Kind : uint8_t { ClockTime, SkyEvent };`
  - `enum Alarms::Event : uint8_t { Sunrise, Sunset, CivilDawn, CivilDusk, NauticalDawn, NauticalDusk, AstronomicalDawn, AstronomicalDusk, SolarNoon, Moonrise, Moonset, Imsak, PrayerSunrise, Dhuhr, Asr, Maghrib, Isha, EventCount };`
  - `struct Alarms::Definition { uint8_t kind; uint8_t hour; uint8_t minute; uint8_t event; int16_t offsetMinutes; uint8_t days; bool on; };` (`days` bit 0 Monday … bit 6 Sunday; 0 = once)
  - `struct Alarms::Place { Astronomy::Observer observer; Zone zone; int ishaAngle; };`
  - `static const int Alarms::MaxAlarms = 4; static const int Alarms::LateSeconds = 600; static const int Alarms::SearchDays = 60;`
  - `static int64_t Alarms::next( const Definition &alarm, int64_t after, const Place &place );` — the first due time (Unix s, whole minute) strictly after `after`, 0 when none within `SearchDays` or the alarm is off.
  - `enum Alarms::Due { Wait, Ring, Skip };` `static Due Alarms::check( int64_t due, int64_t now );` — Wait before `due`, Ring up to `LateSeconds` late, Skip later.
  - `static uint32_t Alarms::placeKey( const Place &place );` — a checksum of the inputs; a cached due time is valid only with the same key.
  - `static bool Alarms::encode( const Definition &alarm, char *text, int size ); static bool Alarms::decode( const char *text, Definition &alarm );` — the portal's "kind|hour|minute|event|offset|days|on".

- [ ] **Step 1: Write the failing test** `tests/AlarmsTest.cpp` with checks (Istanbul 41.0082, 28.9784, UTC+3, isha 17 unless named):
  - `clockWeekdays`: 07:00 Mon–Fri (`days 0x1F`), after Fri 2026-11-20 08:00 local → Mon 2026-11-23 07:00 local.
  - `clockOnce`: 07:00, days 0, after 06:00 → today 07:00; after 08:00 → tomorrow 07:00.
  - `eventEqualsAstronomy`: Sunset +0 → equals `Astronomy::sunDay(...).riseSet.setting.time` rounded to the minute; Maghrib +0 → equals `Sky::prayerTimes(...).times[Sky::Maghrib]` rounded; Moonrise −60 → moonrise − 3600.
  - `ringingDayRule`: Moonrise −60 with days = Monday only, on a week where a Tuesday moonrise is at 00:30 local → rings Monday 23:30; never on Sunday night.
  - `missingEvent`: Moonrise on the day without a moonrise → the next day's.
  - `polar`: Tromsø 69.65, 18.96, UTC+1, Sunrise in 2026-12-15 → 0 (none within 60 days); astronomical dusk at 60 N in June → 0 or a date after the white nights, never a wrong value.
  - `dstChange`: a zone changing from +60 to +120 at 2027-03-28 01:00 UTC; 03:00 daily → 2027-03-28 03:00 at +120 (01:00 UTC), once.
  - `lateAndRepeat`: `check(due, due - 1) == Wait`, `check(due, due) == Ring`, `check(due, due + 600) == Ring`, `check(due, due + 601) == Skip`; `next(alarm, due)` is after `due` (a rung alarm is not found again).
  - `inputsChanged`: `placeKey` differs when latitude, longitude, zone offset, a zone change or the isha angle differs.
  - `codec`: encode/decode round trip; decode rejects hour 24, offset 121, event ≥ EventCount, a wrong field count.

- [ ] **Step 2: Run** `sh tests/run_host_tests.sh` — Expected: FAIL, `Alarms.h` not found.
- [ ] **Step 3: Implement** `main/Alarms.*`: day by day from the local day of `after` for `SearchDays` days: the candidate = the event of that local day (`Astronomy::dayCrossings` for one sun altitude, `Astronomy::moonDay`, `Sky::prayerTimes`) or the clock time, plus the offset, at the zone's offset of that moment (`Zones::offsetAt`); kept when after `after` and its own local weekday is selected (or `days == 0`). The event of the day before is checked too, so that a negative offset can bring it into the day.
- [ ] **Step 4: Run** `sh tests/run_host_tests.sh` — Expected: `Alarms: N checks, 0 failures`, all other suites unchanged.

- [ ] **Step 1:** Every `powerOff()` reason except the 2 % limit and a failed face deep-sleeps instead while `alarmPending()`: panel as in `sleepNow()`, timer = min(next due − margin, 1 h). ## Rulings in this plan (for the owner to check)

- **60 days, not 400:** the spec's 400-day search costs up to about 40 s of astronomy on the
  watch at polar latitudes; the search stops at 60 days, the alarm then shows "--:--" and is
  searched again the next day (it never rings wrongly, and it finds the event once it is
  within 60 days).
- **The Alarms part is the clock page's last part**, not placed after the countdown: inserting
  it would renumber the parts and scramble the saved orders. The owner can move it in the
  portal; orders saved before keep their places (PartOrder fix, Task 5).
